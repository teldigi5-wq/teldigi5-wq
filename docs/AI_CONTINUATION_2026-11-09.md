## Recovery principles

Before continuing any project, inspect its README, source ownership, roadmap, latest open implementation PR base/head, current CI, security findings and release readiness. Do not repeat already recorded milestones. Distinguish **planned**, **code present**, **tested**, **merged**, **deployed**, and **owner-accepted**. Public portfolios and CI demos do not prove operational production readiness.

Use existing GitHub free plans and open-source/local tooling when possible. Keep changes small and reviewable, leave protected main and feature PRs unchanged until full evidence and approval, and never publish sensitive data or bypass security gates.

## How another AI should resume

1. Start from the specific public repository's draft documentation PR, then inspect the actual default branch, roadmaps, issues, security guidance, releases and current PR DAG.
2. Reconcile source commits with any claimed tests; record commands and actual observed results. Never transfer successful CI results to a different SHA.
3. Identify the **next distinct missing milestone**, propose a minimal change, then test and seek review rather than creating duplicate PRs or restarting a completed phase.
4. Preserve cross-repository architecture boundaries, history, evidence, secrets and rollback plans. This index is not a complete branch audit or a certification.
5. Private projects, their owners' checklists and internal links are intentionally *not included* in this public index; consult private repository documentation only through authorized access.

**Scope:** This publicly shareable index does not include the private project handover bundle. Its contents are a dated snapshot, not an assertion of deployment or current security assurance.
